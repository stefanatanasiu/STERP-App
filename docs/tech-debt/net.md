# Technical debt - .NET client framework

Deliberate legacy texture in `dotnet\**`, recorded as CONVENTIONS 3.5 requires. Everything
here is *intentional*: it makes STERP feel like a client that has been maintained since 1994.
One bullet per item: file, pattern, why it is debt, how it would be modernised.

| # | Where | Pattern | Why it is debt | Modernisation |
|---|---|---|---|---|
| 1 | `dotnet\STERP.Legacy.props` | `<OptionStrict>Off</OptionStrict>` for every VB project | Late binding and implicit narrowing conversions turn type errors into run-time errors; `Fmt.Dec(row("Amount"))` compiles whatever the column type is | Turn `Option Strict On` project by project, starting with `STERP.Business`, and introduce typed DTOs instead of `DataRow` |
| 2 | `STERP.Common\SterpSession.cs` | `public static SterpSession Current` - a process-wide singleton of **public mutable fields** (the VB6 client's global `UserRec`) | Any form can change the company or business date under another form's feet; nothing is thread safe; impossible to run two sessions in one process | Inject an immutable `ISessionContext` into the services; make the fields read-only properties set by `LoginService` |
| 3 | `STERP.Common\SterpSession.cs` | `PermissionCache` never expires - a permission answer survives until the company/site is changed | A permission revoked during a shift is still honoured by the client until sign-off (the stored procedure still refuses the posting, so this is a usability bug, not a hole) | Time-box the cache or push an invalidation message |
| 4 | `STERP.Data\SqlHelper.cs` | Static class with a static mutable `ConnectionString` and `CommandTimeout`, one connection opened per call | No unit of work, no ambient transaction, no dependency injection, no connection reuse across a multi-statement screen | Replace with a scoped `ISterpDb` (connection + transaction) resolved per form |
| 5 | `STERP.Data\SqlHelper.cs` | A command "is ad-hoc SQL when the name contains a space" | Clever but fragile heuristic inherited from the VB6 `ExecSP` wrapper | Separate `ExecuteProcedure*` and `ExecuteText*` methods |
| 6 | `STERP.CobolInterop\CobolGateway.cs` | One process-wide `lock` around every LINK | The GnuCOBOL runtime is not re-entrant, so the whole client serialises on the engine; a long COBOL call freezes every window | Host the engine in a pool of out-of-process workers and talk to them over a pipe |
| 7 | `STERP.CobolInterop\CobolGateway.cs` | `public static bool Trace` read once from configuration at class load | Tracing cannot be switched on without restarting the client | Read the setting through a refreshable options object |
| 8 | `STERP.CobolInterop\CopybookParser.cs` | Layouts cached for the life of the process in a static dictionary keyed by copybook name | A rebuilt copybook needs a client restart; `ClearCache()` exists but nothing calls it | Watch `bin\x86\copy` and invalidate, or stamp layouts with the file write time |
| 9 | `STERP.CobolInterop\CopybookParser.cs` | `REDEFINES` is laid over the redefined item without checking that the overlay fits, and `OCCURS DEPENDING ON` is silently unsupported | A malformed COMMAREA copybook produces wrong offsets instead of a diagnostic | Validate lengths and reject unsupported clauses with a clear message |
| 10 | `STERP.Business\System\LoginService.vb` | Three-tier sign-on fallback: `core.usp_GetUserContext`, then direct reads of `core.AppUser` / `core.Company`, then a hard-coded stand-alone SYSADM context for STC and CAL | The emergency sign-on exists so the client starts while the security module is being installed; on a real system it would be a way in | Delete the third tier before the system leaves the demonstration estate; keep tier 2 behind a support switch |
| 11 | `db\procs\core\usp_UiCheckAccess.sql` | Answers from `core.fn_HasPermission` through `sp_executesql` (deferred name resolution) and **denies** when the security module cannot answer | Fixed: the procedure used to insert a six column result set into a two column table variable, swallow the error and fail **open**, so every permission was granted and the menu filter did nothing. It now fails closed, but the indirection through dynamic SQL is still a smell | Reference `core.fn_HasPermission` directly once the security module is guaranteed to be deployed first |
| 12 | `STERP.Business\System\*.vb` | Services return `String` ("" = success, otherwise the message) instead of throwing | 1990s VB habit; the caller cannot tell a business refusal from a technical failure without reading the text | Return a small `ServiceResult` carrying the code, severity and message |
| 13 | `STERP.Desktop\BaseForm.vb` | `Guard(Sub() ...)` swallows every `Exception` into a message box | A programming error looks exactly like a business refusal to the operator | Catch only `BusinessRuleException` and `SqlException`; let the rest reach the global handler |
| 14 | `STERP.Desktop\Forms\System\frmMain.vb` | Menu rows are filtered with `DataTable.Select("ParentMenuCode = '" & code.Replace("'","''") & "'")` | String-built filter expressions (not SQL, so no injection risk) are the old `Recordset.Filter` habit | Build the tree with LINQ or a dictionary lookup |
| 15 | `STERP.Desktop\Forms\System\frmMain.vb` | Built-in fallback menu hard-coded as a pipe-delimited string array | Duplicates `db\seed\05-core-menu-system.sql`; the two can drift | Ship the fallback as an embedded resource generated from the seed |
| 16 | `STERP.Desktop\UiStyle.vb` | Toolbar glyphs painted with GDI+ at start-up instead of using resources | Keeps the repository free of binary files, but the icons are not high-DPI aware and cannot be re-skinned | Ship an icon strip (or SVG) and scale it per monitor |
| 17 | `STERP.Desktop\Forms\System\frmGenericMaint.vb` | The edit panel is rebuilt control by control from `core.MaintColumn` with absolute `SetBounds` co-ordinates, eight fields per column | No layout engine, so long captions clip and the panel does not reflow; this is exactly how the 1990s screens were painted | Use a `TableLayoutPanel` and measure the captions |
| 18 | `STERP.Business\System\MaintService.vb` | Values travel to the database as strings in a small XML document and rely on SQL Server's implicit conversion | A badly typed value fails deep inside `usp_UiMaintSave` with a conversion error rather than at the field | Send typed parameters, or validate client-side against `sys.columns` |
| 19 | `STERP.Desktop\Forms\System\frmApprovals.vb`, `frmExceptions.vb` | `InputBox` from `Microsoft.VisualBasic` for the approval comment and the resolution note | No length validation, no multi-line entry, no way to tell Cancel from an empty note | Replace with a proper modal note dialog |
| 20 | `dotnet\STERP.Tests` | A home-grown reflection + TAP harness instead of a test framework | No fixtures, no parallelism, no assertion library; tests that touch the database clean up by hand in a `finally` | Move to NUnit with a transaction-scoped fixture, keeping the TAP output for `run-tests.ps1` |
| 21 | `dotnet\STERP.Tests\Framework\DataTests.cs` | Database tests insert `ZZT` / `ZZW` rows into `core.Currency` and delete them afterwards | Not transactional - a crash leaves the rows behind | Wrap each test in a `TransactionScope` that is never committed |
| 22 | `STERP.Common\SterpConfig.cs` | `STERP.INI` in the program directory overrides `App.config`, read once and cached, failures ignored | The install procedure still tells the site to "edit the INI"; a typo silently does nothing | Single configuration source with validation at start-up |
| 23 | `STERP.Desktop\Forms\System\frmMain.vb` | A 1 second `Timer` polls CAPS/NUM and re-pings the engine every 60 ticks | Polling instead of events; a slow engine ping blocks the UI thread for its duration | Subscribe to key state changes and ping on a background worker |
| 24 | `STERP.Desktop\UiStyle.vb` | The Windows 2000 palette is hard-coded and `ApplyPalette` walks the whole control tree on every `OnShown`, overwriting any colour a form set in `Load` | A form that genuinely needs a different colour has to set it after `OnShown`; the walk is O(controls) on every activation of a new window | Make the palette a theme object the controls read, or apply it once with a `ControlAdded` hook |
| 25 | `STERP.Desktop\UiStyle.vb` | `ApplyPalette` forces `FlatStyle.Standard` on every button, group box and tick box | The real classic look is the *system* renderer, but on Windows 10/11 that renderer ignores `BackColor`; WinForms' own 3D drawing is a near miss, not the genuine article | Draw the controls with `ControlPaint`/`DrawFrameControl`, or run the client with a classic theme |
| 26 | `STERP.Business\System\ReportService.vb` | `Run` starts the batch EXE and `WaitForExit`s **on the calling (UI) thread** | A long report freezes the whole client, exactly as the VB6 version did; the Job Monitor cannot show it progressing | Run the process on a background worker and report progress through `core.JobRun` |
| 27 | `db\procs\core\usp_UiMenuLoad.sql`, `usp_UiReportList.sql` | A `CURSOR` calls `core.usp_UiCheckAccess` once per distinct permission code, then an iterative `DELETE` loop prunes emptied branches | Row-by-row instead of set based; the menu costs one round trip per secured permission at every sign-on and company switch | Expose the security module as a table valued function and resolve the whole menu in one statement |
| 28 | `run\work\qa-screens.ps1` | Look-and-feel QA drives the client with `BM_CLICK`, posted window messages and UI Automation, and captures with `PrintWindow` | Windows refuses to give a background process the foreground, so keystroke injection is unreliable and the script has retry loops around every step | Build the screens from a headless render harness, or use a dedicated UI test runner |
