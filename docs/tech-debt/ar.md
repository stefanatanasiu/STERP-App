# `ar` – intentional technical debt

Deliberate legacy texture in the Sales Ledger. The module is notionally a 1991 MVS port, so the debt
is the debt a 35-year-old debtors ledger really accumulates. Each entry: **what**, **where**,
**why it is there**, **how a modernisation would remove it**.

| # | File / pattern | What it is | Why (the legacy story) | Modernisation hint |
|---|---|---|---|---|
| 1 | `cobol\copy\RCPTALOCCA.cpy` – `RA-ALLOCS OCCURS 20` | A receipt may be spread over at most 20 open items in one call. | 1991 CICS COMMAREAs were capped at 32 KB; every table was a fixed `OCCURS` sized on "the biggest remittance anyone had seen". | Replace the COMMAREA with a streamed/paged contract and let the allocation count be unbounded; page server-side instead. |
| 2 | `cobol\copy\ARINVPSTCA.cpy` – `AI-LINES OCCURS 25`, `AI-VATS OCCURS 6`, `AI-MISSING OCCURS 10` | A 25-line invoice limit, six VAT codes per invoice and ten "missing content" messages. | Same COMMAREA budget. Six VAT codes was "obviously enough" when there were three rates. | A message contract with repeated groups (JSON/protobuf) and a validation result list that is not capped. |
| 3 | AR-wide – SQL built with `STRING` into `SQLIO-STMT` and bound by **position** | Every statement is a literal assembled at run time with `?` placeholders counted by hand (`SQLIO-PARM-CNT`). | Embedded SQL preprocessors were not available to this port; `SQLIO` was written as a thin call-level shim. | Named parameters and generated data-access code. The positional count is a real defect source – `RCPTALOC 3200-REVERSE-ALLOCATION` shipped with `21` where the statement had 25 placeholders and failed only at run time. |
| 4 | `cobol\online\ar\RCPTALOC.cob` – one multi-statement batch per unit of work | The reversal does an `INSERT`, two `UPDATE`s on `ar.Allocation`/`ar.OpenItem` and a trailing `SELECT` in a single `SQLIO` call, with `SET NOCOUNT ON;` in front so the shim fetches the echo and not a row count. | Round trips to the database were the expensive thing; one call per unit of work was the rule. | A stored procedure (or a repository method) with an explicit transaction and `OUTPUT INSERTED.*`, so neither the statement order nor `SET NOCOUNT ON` is load-bearing. |
| 5 | `cobol\copy\ARWORK.cpy` – `AR-RC-BAD VALUE 08 THRU 16` vs `AR-RC-STOP VALUE 06 THRU 16` | Two overlapping severity conditions: `06` is a *hold*, which is informational to an enquiry but fatal to anything that posts. | The hold code was added when the D-22 write-off approval rule arrived, after the `AR-RC-BAD` tests had already been written everywhere. | One result type with an explicit outcome (`Accepted` / `Held` / `Rejected`) rather than an ordered numeric code that each caller re-interprets. |
| 6 | `cobol\copy\ARWORK.cpy` – `AR-ISO-DATE` (`yyyy-mm-dd`) and `AR-COMPACT-DATE` (`yyyymmdd`) side by side | Two date layouts in one working-storage copybook, converted field by field. | SQL Server style `112` returns `yyyymmdd` and style `126` returns the ISO form; programs picked whichever the original author remembered. | A real date type end to end. The dual layout is a live defect source – `ARADJUST` parsed a style-`112` discount due date through the ISO layout and silently mis-classified settlement discounts as write-offs. |
| 7 | AR-wide – reason codes are 7-character string literals (`RCP0029`, `ADJ0020`, `BDR0010`, `DDM0052`) | The code *and* its English sentence are built inline at each rejection point. | Message files (BMS/`MSGFILE`) were per-transaction; nobody wanted another dataset to maintain. | A message catalogue keyed by code, with translations and a single place to document each rule. Tests then assert the code, never the prose. |
| 8 | `cobol\online\ar\RCPTALOC.cob` – `2450-CLASSIFY` | Allocation kind (`EXACT`, `PARTIAL`, `DISCOUNT`, `WRITEOFF`, `CROSSCCY`) is decided by an ordered `EVALUATE TRUE` where the first matching leg wins. | Classification grew one leg at a time between 1991 and 2026; the order encodes undocumented precedence. | Make the precedence explicit (a rule table or a decision record) so adding a sixth kind cannot silently re-classify the existing five. |
| 9 | `cobol\online\ar\RCPTALOC.cob` – `2050-READ-SOURCE` / `3100-READ-ALLOCATION` share one `WS-SRC` record | The allocation reader reuses the *receipt* reader's record layout, so `TargetOpenItemId` lands in `WS-S-RATE` and `AppliedAmount` in `WS-S-RESIDUAL`. | Working storage was scarce and the two reads "had the same shape". | Typed row records (or a generated DTO) per query. The overload is why the reversal's parameter mapping was wrong for a year. |
| 10 | `cobol\online\ar\LATEINT.cob` – base rate and the 40/70/100 bands | The band boundaries (GBP 1,000 / 10,000) and the statutory margin (base + 8%) are read from `core.Parameter`, but the *shape* of the rule (three bands, one margin) is hard-coded. | The rule has only ever changed by moving the numbers. | Express the bands as data (ordered rows: upper bound → compensation) so a fourth band needs no recompile. |
| 11 | `cobol\batch\ar\DDCOLL.cob` | Bacs **Standard 18** fixed-width 100-byte records built with `STRING` into `PIC X(100)`; AUDDIS/transaction codes (`0N`, `0C`, `01`, `17`) as literals. | Std-18 **is** a fixed-width externally mandated format. | Keep the format but isolate it behind a formatter with a golden-file test, so the collection logic no longer knows about column positions. |
| 12 | `cobol\online\ar\DDMAND.cob` – modulus check on sort code/account | Hand-coded modulus weighting table. | The VocaLink table was typed in once and updated by hand. | Call a bank-detail validation / Confirmation-of-Payee service instead of shipping a static table. |
| 13 | `cobol\online\ar\DDMAND.cob` – permission codes as literals | `AR.DD.MANDATE.MAINT` / `AR.DD.COLLECT.RUN` are string literals checked through `PERMCHK`; a typo is only discovered when a user is silently held at `06`. | The permission catalogue and the programs were maintained by different people. | Generate the permission constants from `core.Permission` (or fail the build when a referenced code is not seeded). |
| 14 | `cobol\batch\ar\AGEDDEBT.cob`, `STATEMNT.cob`, `DUNNING.cob`, `ARRECON.cob` | Report Writer, 132 columns, `run\spool\*.lst`. | Everything printed on a line printer; 132 columns is the paper width. | Emit a structured result set (the existing `core.ReportDef`) and render to PDF/HTML; keep the `.lst` only for the archive. |
| 15 | `cobol\batch\ar\EINVUBL.cob` | UBL 2.1 XML written by `STRING`-ing tags into `PIC X(200)` lines, with no schema validation. | Bolted on in 2019 to a program that had no XML support. | Produce the invoice as a structured document in a sidecar service that validates against the Peppol BIS schema. |
| 16 | `cobol\batch\ar\STATEMNT.cob` – ageing buckets recomputed | Current/30/60/90/120+ buckets are recomputed by the statement run instead of reading `AGEDDEBT`'s result. | Two programs, two authors, one rule. | One ageing service (view or proc) consumed by both; the bucket edges become configuration, not code. |
| 17 | `ar.OpenItem` carries both document currency and GBP columns (`ResidualAmount` / `ResidualAmountGBP`) | Every amount is stored twice and both must be updated together. | The 1991 ledger was sterling-only; multi-currency was added by duplicating columns rather than normalising. | Store the document amount plus the rate and derive the base amount in a view, so a rate correction cannot leave the two out of step. |
| 18 | `ar.OpenItem.SettlementStatus` is a maintained string (`OPEN`/`PARTIAL`/`SETTLED`/`REVERSED`) | The status is set by every program that moves a residual, including by a `CASE` inside the reversal statement. | Denormalised in the 1990s because the open-item screen was too slow over the allocation detail. | Derive the status in a view from the residual, or maintain it in exactly one procedure. |
| 19 | AR-wide | Amounts are `COMP-3` `S9(11)V99`, FX rates `S9(9)V9(8)`, percentages `S9(3)V9(4)`. | Packed decimal was the only exact money type. | Keep exact decimals (`decimal(19,4)` / `decimal(19,8)`) – do **not** "modernise" to floating point. The lesson is to carry the scale explicitly. |
| 20 | AR-wide | Dates are `PIC 9(8)` `yyyymmdd` integers and all arithmetic goes through `DATECALC`. | Y2K remediation expanded 6-digit dates to 8 rather than introducing a date type. | A real date type end to end; `DATECALC` becomes a business-calendar service (working days, Bacs processing days, the six-month bad-debt clock). |
| 21 | `cobol\online\ar\ARADJUST.cob` – reason codes in a comma-delimited literal | The valid adjustment reasons (`SMALLDIFF,SETTLEDISC,GOODWILL,BADDEBT,...`) are a single `STRING` literal scanned with `INSPECT`. | A reference table "was not worth a file" in 1991. | A reference table with effective dates, so a new reason does not need a recompile. |
| 22 | `cobol\online\ar\CREDCHK.cob` – exposure recomputed per call | All five legs are re-aggregated on every order line check, with no cache and no snapshot. | Order volumes were small and the check ran once per order. | Maintain the exposure incrementally (event-sourced or a materialised aggregate) and keep the full recomputation as a reconciliation job. |
| 23 | AR-wide – no optimistic-concurrency token on `ar.OpenItem` | Last write wins; two clerks allocating the same invoice rely on the surrounding transaction only. | Screens were single-user per account in CICS. | Add a `rowversion` and surface conflicts to the user instead of silently overwriting. |
| 24 | `cobol\tests\ar\*` | Tests create and then `DELETE` their own `ZZ`-prefixed customers, open items and mandates against the live schema. | There was no test database; tests ran against a copy of production. | Transactional fixtures or a disposable container database per test run. |
| 25 | `db\seed\91-ar-demo.sql` | Demo invoices, receipts and disputes are seeded as literal `INSERT`s with dates relative to a fixed "today". | The demo had to work without running the batch suite first. | Generate the demo set by driving the real programs, so the data cannot contradict the rules. |
