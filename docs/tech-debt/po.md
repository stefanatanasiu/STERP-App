# Technical debt — purchase order management (`po`)

Deliberate legacy texture in the 1998 ACUCOBOL-GT distribution suite. Each item is correct and
tested; each one is also a modernisation target.

| File | Pattern | Why it is debt | Modernisation hint |
|---|---|---|---|
| `cobol\copy\POACCNTS.cpy` | Nominal account numbers (`1100`, `2010`, `5200`, `5220` …) hard-coded in a copybook, duplicating `fin.EventAccountMap` | A chart-of-accounts change has to be made in two places and a recompile is needed; the two can silently diverge | Resolve every leg from `fin.EventAccountMap` at run time and delete the copybook constants |
| `cobol\copy\POACCNTS.cpy` | D-08 tolerance baseline compiled in as `VALUE` clauses (`PO-POL-OVER-MAX-PCT VALUE 5`, `PO-POL-PRICE-ABS VALUE 50` …) | Policy changes require a build even though `po.ToleranceRule` and `core.Parameter` already hold the same numbers | Make `po.ToleranceRule` mandatory and fail loudly when no rule row exists, instead of falling back to literals |
| `cobol\online\po\POPOST.cob` | Near-verbatim copy of `cobol\online\ap\APPOST.cob` (same paragraph numbers, same staging SQL, different reason-code prefix) | Two ledgers maintain the same `fin.JournalStage` INSERT; a column change must be made twice | Promote one shared `GLSTAGE` service with a module code in its work area |
| `cobol\online\po\POPOST.cob` | Reason codes carry a fixed numeric suffix (`POP0001`..`POP0009`) assigned by hand | Codes get reused or skipped as the program grows, and there is no central registry | Register reason codes as reference data and generate the copybook |
| `cobol\online\po\TOLCHK.cob` | `4200-WORK-DAYS` counts business days by calling `DATECALC ADDBUS` one day at a time, capped at a magic `60` iterations | O(n) service calls for what should be one query; the cap silently degrades to calendar days | Add a `BUSDIFF` function to `DATECALC`, or a `core.fn_BusinessDaysBetween` table function |
| `cobol\online\po\TOLCHK.cob` | `PERFORM … THRU …-EXIT` with `GO TO …-EXIT` early returns throughout | Era-correct, but control flow is hard to follow and a mis-typed exit label fails silently | Convert to inline `PERFORM`/`EXIT PARAGRAPH` once the module is stable |
| `cobol\online\po\LANDCOST.cob` | `OCCURS 40 TIMES` recipient table in the COMMAREA, silently truncated by `IF LC-LINE-CNT > 40 MOVE 40` | A shipment covering more than forty receipt lines is quietly under-allocated rather than rejected | Reject above the limit, or move the allocation into a set-based stored procedure |
| `cobol\online\po\LANDCOST.cob` | `CALC` treats a non-zero `LC-DELTA-GBP` as the allocation target, overriding the estimate | Implicit mode switching driven by a data value rather than an explicit function | Add an explicit `CALCDELTA` function and make `LC-DELTA-GBP` output-only |
| `cobol\online\po\LANDCOST.cob` | Consumed-unit share is debited to `PO-ACC-SCRAP` (`5110`) as a stand-in for the costing module's cost-of-sales account | The purchasing module is guessing at a costing-owned posting | Call the costing module's landed-cost/MWA service for the consumed portion once it exists |
| `cobol\online\po\POPRICE.cob` | `2000-PRICE` and `2200-APPLY-BREAK` both parse the price row with `FUNCTION NUMVAL` on fixed-width text columns | Conversion rules are repeated and a widened column needs edits in several paragraphs | Use typed result-set binding in `SQLIO`, or return pre-formatted values from a view |
| `cobol\online\po\POPRICE.cob` | Currency mismatch returns `04` and *overwrites* the caller's `PR-CURRENCY` with the agreement currency | A warning quietly changes an input field; a careless caller will take the wrong currency as agreed | Return the agreement currency in a separate output field and leave the request untouched |
| `db\tables\80-po\06-CommitmentControl.sql` | `po.Commitment` is an append-only movement table with no balance view | Every enquiry has to aggregate the movements itself and will invent its own stage rules | `po.vw_CommitmentBalance` now exists in `db\procs\po\usp_PoEnquiry.sql`; make it the **only** supported read path and stop callers aggregating `po.Commitment` directly |
| `db\tables\80-po\05-SourcingPricing.sql` | `po.PurchasePrice` duplicates supplier prices and breaks already modelled in `inv.ItemPartner` | Two price books can disagree about the same supplier/item | Decide one owner — purchasing agreements in `po`, catalogue cross-references in `inv` — and make the other a view |
| `cobol\online\po\POAPPRV.cob` | Its own 64-character change-detection hash (`8000-HASH`), a near-duplicate of `cobol\online\ap\APHASH.cob` with different seeds | Two modules maintain two hand-rolled hashes for the same purpose; a difference in either silently changes approval behaviour | Promote one shared `STHASH` service, or compute `HASHBYTES('SHA2_256', …)` in a view and let COBOL read it |
| `cobol\online\po\POAPPRV.cob` | The line part of the content hash is `CHECKSUM_AGG(CHECKSUM(...))` | `CHECKSUM` is not collision resistant, so two genuinely different line sets could in principle share one approval | Replace with `HASHBYTES` over a deterministic line projection |
| `cobol\online\po\POSUPCHK.cob` | The D-29 mandatory evidence set is a compiled `WS-MANDATORY-TABLE` of four literals | A policy change needs a recompile, even though `po.SupplierDiligence.IsMandatory` already carries the same fact | Drive the mandatory set from `core.Parameter` or a `po.DiligencePolicy` table |
| `cobol\online\po\POORDER.cob` | `3400-WRITE-LINE` deletes and reinserts the line (and its schedules) on every `ADDLINE` | Re-keying one field throws away the schedules and the line identity; any foreign key to `PurchaseOrderLineId` would break | Make `ADDLINE` a true `MERGE` on the line and leave the schedules alone |
| `cobol\online\po\POORDER.cob` | Delegates `ACKNOWL`/`AMEND`/`CALLOFF`/`COPY` to `POAMEND` by passing its own `DFHCOMMAREA` straight through | Two programs share one COMMAREA and one reason-code namespace, and neither owns the contract | Split into two COMMAREAs, or make `POAMEND` a private subprogram with its own work area |
| `cobol\online\po\POAMEND.cob` | `CALLOFF` draws down `po.BlanketBalance` as a step separate from creating the call-off order | A crash between the two leaves the blanket drawn down with no order against it | Do the draw-down and the order creation in one stored procedure under a single transaction |
| `cobol\online\po\PAYTERMC.cob` | Policy and statutory defaults compiled in as `WS-DEF-POLICY 30` / `WS-DEF-STATUTORY 60`, used whenever `PARMGET` has nothing | A statutory change becomes a code change, and a missing parameter fails silently to a literal | Make `PO.TERMS.STATMAX` mandatory and fail loudly when it is not held |
| `cobol\online\po\BUDGCHK.cob` | The split-purchase window is a compiled `WS-SPLIT-WINDOW 30` and only looks at `po.Requisition` | Orders raised without a requisition escape the aggregation entirely | Aggregate `po.Commitment` by requester as well, and read the window from `core.Parameter` |
| `cobol\copy\TESTKITP.cpy` (shared) | `DISPLAY … UPON SYSOUT` added so the `acu` dialect does not treat TAP output as a CRT display | A dialect quirk leaks into a shared foundation copybook | Set `console-is-crt: no` for the `acu` build, or pass `-fno-console-is-crt`, and revert the copybook |

## Goods receipt, returns, imports and closure (added with RECEIPT / SUPPRET / IMPVAT / POCLOSE)

| File | Pattern | Why it is there | Modernisation hint |
|---|---|---|---|
| `cobol\online\po\RECEIPT.cob` | The receipt header and lines are written and committed by SQLIO **before** `POPOST` is called, rather than everything sharing one transaction. | `fin.usp_PostJournal` owns its own transaction; holding an SQLIO transaction across it would let a procedure that throws doom the outer transaction. The correlation id makes the posting idempotent, so a retry after a failure repeats the work without doubling it. | A single unit of work (outbox or a transactional service boundary) would remove the compensating-retry reasoning entirely. |
| `cobol\online\po\RECEIPT.cob` | Twenty receipt lines in a fixed `OCCURS` table, twelve for `SUPPRET` and fifteen for `IMPVAT`; the count is silently clamped. | 1998 CICS COMMAREAs were fixed length, and the screens were built around a page of lines. | Variable-length request payloads; paginate in the client rather than truncating in the engine. |
| `cobol\copy\POACCNTS.cpy` | Nominal account numbers are compiled into a copybook **and** seeded into `fin.EventAccountMap`. | The 1998 suite kept its chart in one copybook so a chart change was a single recompile; the seed is the modern source of truth and the literals are the fallback. | Delete the literals and read the mapping; keep one source of truth. |
| `cobol\online\po\POCLOSE.cob` | Function names are capped at eight characters, so the short-close function is `SHORTCLS` and not `SHORTCLOSE`. | `CA-FUNCTION` is `PIC X(8)` in `STCAHDR`, inherited from the CICS transaction-code era. A nine-character literal silently truncates and falls through to the "unsupported function" branch. | Widen the header field, or move to a named-operation contract where truncation is impossible. |
| `cobol\online\po\IMPVAT.cob` | Duty attributable to units already sold is posted to `5110` *Material usage variance* because there is no purchasing-specific cost-of-sales account. | The 1998 chart had no landed-cost-on-consumed-units account and nobody wanted a chart change for it. | Add an explicit account; the posting intent is already documented in `db\seed\80-po-eventmap.sql`. |
| `db\seed\80-po-eventmap.sql` | `PO.RECEIPT` and `PO.SERVICEACCEPT` live in `10-fin-eventmap.sql` while the other seven purchasing events live here. | Module seeds must not edit the shared finance seed; the split is ownership, not design. | Consolidate event mappings into one owned-by-module table once the deployment order is module-aware. |

## Client facades and screens (added with the Purchasing forms)

| File | Pattern | Why it is there | Modernisation hint |
|---|---|---|---|
| `dotnet\STERP.Business\Purchasing\RequisitionService.vb`, `PurchaseOrderService.vb` | The COMMAREA carries **one line at a time**, so the facade keeps the lines captured in this sitting in its own `DataTable` for the grid; re-opening the screen loses the working list and the grid falls back to the enquiry. | `POREQCA` / `POORDERCA` have no `OCCURS` line table - the 1998 screens added a line, pressed Enter and redisplayed from the file. | Return the document with its lines (a result set or a repeating group) and bind the grid to it. |
| `dotnet\STERP.Business\Purchasing\GoodsReceiptService.vb` | The validated `RECEIPTCA` buffer is **held in the service between calls**, the screen writes counted quantities into it, and `CONFIRM` links with the same buffer. | A faithful pseudo-conversation: the COMMAREA is the state, exactly as CICS kept it between transactions. | A receipt document with an identity of its own, saved as a draft, would survive a crash and allow two people to count. |
| `dotnet\STERP.Desktop\Forms\Purchasing\frmPurchaseOrder.vb` | Twenty-odd fields of the order and its line are entered in one window, with the amendment panel on the same screen as capture. | One screen per transaction code was the house style; a buyer learned the field order and never looked at the labels again. | Split capture, approval and amendment into task-shaped screens with their own permissions. |
| `dotnet\STERP.Desktop\Forms\Purchasing\frmGoodsReceipt.vb` | The counted quantity is typed into an edit panel and pushed into the selected grid row with a button, because the grids are read only. | COM-024 forbids editable grids - the 1998 client had no in-cell editing. | A modern grid with validation per cell, or a scanner-driven count that never touches a keyboard. |
| `dotnet\STERP.Tests\Purchasing\PurchasingTests.cs` | Tests skip (`# SKIP`) when a procedure or a COBOL program is not in the build rather than failing. | Modules are deployed independently and the harness must stay green while a neighbour is mid-deployment. | Contract tests against a disposable database that is always complete. |
| `cobol\batch\po\PODOC.cob` | A reprint is detected by counting earlier `core.JobRun` rows whose free-text `Arguments` column is `LIKE '%ORDER=<n>%'` | The job log is an operations record being used as a business fact; an argument typed in a different order, or a run of a differently named job that happens to mention the order, changes the answer | Record document issues in their own table (`po.DocumentIssue`: order, version hash, issued at, issued by, copy number) and leave the job log to operations |
| `cobol\batch\po\SUPPPERF.cob` | The measure row is replaced with a `DELETE` followed by an `INSERT` on two separate `SQLIO EXEC` calls, with no surrounding transaction | A failure between the two leaves the period with no measure at all rather than the old one | One `MERGE`, or `SQLIO BEGN`/`COMT` around the pair |
| `cobol\batch\po\REQGEN.cob` | Proposals are extracted into a `WORKING-STORAGE` table of 2,000 occurrences and only then raised, because `SQLIO` cursors are a shared global resource and `POREQ` would reuse the one the scan is holding | A hard limit on a batch run, and a silent warning when it is reached | Connection-scoped cursors, or a server-side set-based proposal that the service consumes in pages |
| `cobol\batch\po\OVERDUE.cob` | Lateness is computed twice in SQL with `DATEDIFF(day, ..., CAST(? AS date))` and the minimum-days filter is then applied in COBOL | The database returns every open schedule and the program throws most of them away; on a large order book that is a lot of wasted I/O | Push the threshold into the `WHERE` clause, or expose `po.usp_OverdueSchedules` to the report |
| `db\seed\92-po-demo.sql` | Demonstration supplier sources, prices and re-order points are derived from `ABS(CHECKSUM(ItemCode))` so that the same database is produced on every deploy | A checksum is not a documented hash; a SQL Server upgrade could in principle change the data a demo depends on | Seed an explicit fixture table, or generate the data once and keep it as rows |
| `db\seed\81-po-menu.sql` | The purchasing number series (POREQ, POORD, POSRC, PORCP, PORTN) are seeded by the module because `NUMGEN` keys on five-character series codes while the foundation seed only carries the four-character document series PREQ/PORD | Two registries describe the same thing, and a document type that nobody seeds simply fails at run time with `no number series` | One series registry keyed on document type, with the series code derived rather than typed |
| `cobol\batch\po\PODEMO.cob` | Each service call is given its own correlation id `PODEMO-<CO>-<nnn>` from a counter that depends on the order the scenarios are performed in | Insert a scenario in the middle and every later document asks `NUMGEN` for a different number than it did before | Derive the correlation id from the business key of the document being built, not from a run counter |
