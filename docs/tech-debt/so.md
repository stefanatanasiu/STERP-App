# Technical debt — sales order management (`so`)

Deliberate legacy texture in the sales suite. Each item works and is tested; each one is also a
modernisation target.

| File | Pattern | Why it is debt | Modernisation hint |
|---|---|---|---|
| `cobol\online\so\PRICING.cob` | The candidate query is built by `STRING`ing SQL text together and bound to nine positional parameters, four of which are the same date | A new precedence rule means editing concatenated text and renumbering parameters by hand; a mis-numbered parameter fails at run time, not at compile time | Move the candidate selection into `so.usp_PriceEnquiry` (which already reproduces it) and let the program consume the result set |
| `db\procs\so\usp_PriceEnquiry.sql` | Reproduces `PRICING`'s precedence (level, scope, quantity break, effectivity) in T-SQL so a screen can explain a price | Two implementations of one rule; a change to the precedence must be made in both or the explanation will disagree with the price actually charged | Make the procedure the single source of candidates and have `PRICING` call it, leaving only the choice in COBOL |
| `db\views\so\01-so-views.sql` | Net unit price is recomputed in four places as `UnitPrice / PricePerQty * (1-d1) * (1-d2)` | `SODISC` owns the discount sequence; the views repeat the simple half of it and would silently diverge if a third discount or an allowance were added | Persist `NetUnitPrice` (and `NetAmountGBP`) on `so.SalesOrderLine` when the line is priced, and have the views read it |
| `db\views\so\01-so-views.sql` | GBP values are derived as `document / FxRate` from the header rate | The line carries no GBP amount of its own, so a rate correction silently restates history | Snapshot the GBP amount on the line at acceptance, as `ar` and `ap` do for invoices |
| `ar.Customer.PriceListCode` / `so.PriceList.PriceGroup` | The customer's price list code doubles as the price group — the seed sets `PriceGroup` equal to the list code so group lists resolve | There is no price-group master; a customer can be pointed at a list that does not exist, and nothing notices until pricing returns no candidate | Add a `so.PriceGroup` master with a foreign key from `ar.Customer`, and separate "which list" from "which group" |
| `db\seed\93-so-demo.sql` | Demonstration documents are numbered in a hand-reserved `900000` band instead of being drawn from `core.NumberSeries` | The reservation is a convention, not a constraint; a series whose counter ever reaches 900000 will collide | Produce demonstration documents by running the programs, or register a `DEMO` series per document type |
| `db\seed\93-so-demo.sql` | Header money is recomputed from the lines by an `UPDATE` at the end of the script | The totals are derived data stored on the header, so every writer has to remember to maintain them | Compute header totals in a view or a persisted computed column, or make `SOACCEPT` the only writer |
| `so.SalesOrder` | Four independent status columns (`CommercialStatus`, `ReleaseStatus`, `FulfilmentStatus`, `BillingStatus`) each guarded by its own `CHECK` | Nothing in the database forbids an impossible combination such as cancelled-and-despatched; the state machine lives only in `SOACCEPT` and `DESPATCH` | Add a transition table and a trigger, or model the lifecycle explicitly and derive the four columns |
| `db\procs\so\*.sql` | Business error numbers (`STERP-E-1901`..`1905`) are allocated by hand from a block the module claimed, parallel to the COBOL block `14xx`..`18xx` | Numbers are reused or skipped as the module grows and there is no registry a support desk can search | Register error codes as reference data and generate both the COBOL copybook and the T-SQL `THROW` text |
| `db\seed\73-so-maintdef.sql` | The generic maintenance screen lets a user edit a price list line in place, although the effectivity dates are supposed to be the audit trail | An in-place edit silently restates what historical orders were priced from | Make `so.PriceListLine` insert-only in the maintenance definition and add a "supersede from" action |
| `db\procs\so\usp_SalesOrderEnquiry.sql` | Line result set re-reads `so.SalesOrderLine` with a correlated sub-query to map the view row back to its order | A join written as a sub-query because the view does not expose `SalesOrderId` | Expose `SalesOrderId` on `so.vw_SalesOrderLineProgress` and join directly |
| `db\procs\so\usp_SalesBacklog.sql` | Five near-identical `SELECT` blocks, one per grouping | Copy-and-paste arithmetic; a change to the backlog valuation has to be made five times | Group by a computed key expression chosen once, or return the detail and let the report writer group |
| `db\seed\72-so-menu.sql`, `73-so-maintdef.sql` | Permissions are granted to role codes with `WHERE EXISTS` guards rather than failing when the role is missing | A typo in a role code leaves a screen quietly unreachable | Fail the seed when a referenced role or permission does not exist |
| Demonstration data | The seed stops at "picked": no despatch, COGS journal or sales invoice is seeded | A reviewer reading only the seed sees an incomplete sales cycle | Keep it — the events must come from the programs. `SODEMO` now drives despatch, invoicing and returns, and `build\demo-data.ps1` runs it |
